# Historical JEV validation and changes — October 28, 2026

> Archived development record. Several experiments below were subsequently reverted or superseded. The current protocol has two questions, receives only the camera image, and has no active braking command. See [RESULTS.md](RESULTS.md) for current status. The measurements below retain their original scope; this translation does not claim that old tests validate today's source.

## Blue, taller barriers

All **1,208 barriers** in the saved scene were updated to **1.5 m** tall, up from 0.9 m (**+66.7%**), with their bases kept at ground level. The shared `Rail` material became blue RGB **(0.02, 0.22, 0.95)**. The material and generator were updated so regeneration preserves those settings.

Checks against the saved scene verified barrier count, all heights, and material references. Runtime/editor compilation passed with **0 errors and 0 warnings**. No automatic Windows rebuild, driving run, or API call was performed for this change.

## Historical blue-barrier brake prompt — later removed

The then-existing brake question and its `apply`/`release` criteria explicitly asked for braking before contact when the image suggested a collision trajectory toward a blue barrier or another obstacle. The prior lost-road and unsafe-continuation conditions remained, and applying that command canceled throttle.

Runtime compilation passed with **0 errors and 0 warnings**. No API or driving comparison measured that prompt's effect. The entire brake question and command were later removed; this section is not a description of the current API.

## Explicit yellow-centerline prompt

The general task and steering question were changed to treat the dashed yellow centerline as the desired path. Instructions asked the model to read several consecutive dashes, anticipate curvature, steer smoothly, and use road edges if markings were unclear. At that point throttle, the old brake question, and answer options were unchanged; the dynamic input remained the JPEG only.

Runtime/editor compilation passed with **0 errors and 0 warnings**. No API call or driving comparison was performed specifically for this prompt update. The centerline instruction remains in the current two-question protocol.

## Denser center dashes

Dash spacing was reduced from 8 m to **4 m**, keeping length **1.6 m** and width **0.12 m**. The saved scene changed from 60 to **120 dashes**. A startup helper was added to update older scenes. Trees and the JEV protocol were unchanged by this visual edit.

Runtime compilation passed with **0 errors and 0 warnings**. No API or driving test was performed specifically for denser markings.

## Vehicle telemetry input reverted

An intermediate experiment sent `state.vehicle` alongside the image. At the owner's request, that payload field, telemetry collection for the request, and vehicle-state instructions were removed. The original image-only task and questions were restored at that stage; later centerline wording and the two-question change superseded those original strings.

Trees, the large decision panel, and startup configuration were kept. Local HUD/log telemetry also remained. Runtime and editor scripts compiled without errors or warnings; no new API or driving run validated the rollback.

## Low-poly roadside trees

**133 trees** were generated at startup beyond the barriers, using simple trunks, six-sided crowns, and deterministic size/color variation. Placement checked distance from the whole circuit to keep crowns off the road. Trees added no colliders. At the time of this edit, JEV still used the intermediate vehicle-telemetry request.

A Windows build succeeded with **0 errors and 0 warnings**. A short manual test passed with **0 resets** and **0 API calls**. Tree visibility was inspected in both the front-camera and observer views. Screenshots and a report are in [TreesEvidence](TreesEvidence/). No test measured whether trees improved JEV driving.

## Intermediate image-plus-telemetry experiment — later reverted

The client temporarily sent speed, applied steering, yaw rate, throttle/brake state, limits, and requested decision interval with the image. All three questions referenced those values. A large top-right panel displayed the original model choices and distinguished active decisions, waiting, pause, and the then-existing safety braking state. The camera preview was placed below it.

Runtime and editor assemblies compiled with `dotnet build --no-restore`: **0 errors and 0 warnings**. Unity also passed **188 checks**, including the telemetry payload, units, and sign convention. No API or driving test validated that update. The image-only driving measurements below therefore do not establish telemetry effectiveness at high speed.

The telemetry input was subsequently removed, and the current panel has steering and throttle rows only.

## Removing the original color-based driver

The earlier color-based autonomous algorithm was removed from the source and the player. Only Manual and JEV Vision remained. Historical local-controller laps are preserved in [HISTORY-2026-10-25.md](HISTORY-2026-10-25.md); they are not JEV driving results.

At the initial JEV-only stage:

- The Unity 6000.3.26f1 Windows build succeeded with **0 errors and 0 warnings**.
- **187 checks** passed for the protocol, parsing, two driving modes, migration of the retired serialized mode, geometry, and checkpoints.
- `LocalVisionDriver.cs` and its `.meta` file were absent; the class name was also absent from compiled player metadata.

These counts belong to earlier source snapshots. Reused check/build filenames do not make them proof of current validation.

## Historical camera-only payload audit

The audit of those 13 requests verified:

- `state` contained only `camera` and a static `task` instruction.
- The earlier questions were steering, throttle, and brake. No vehicle position, speed, distances, or track geometry were added.
- JPEG bytes decoded from request assets matched all 13 saved frames.
- Applied autonomous commands had source `jev`, HTTP 200, and outcome `applied`.
- Checkpoints and evaluated distances stayed inside the evaluator and did not generate driving controls.

Reports, CSV files, requests, responses, frames, and screenshots are in [JevEvidence](JevEvidence/). The historical [final-summary.json](final-summary.json) summarizes five player tests, while [payload-audit.json](JevEvidence/payload-audit.json) records request checks. Authorization headers and key values were not stored.

Longer budgeted driving and a complete JEV lap remained unverified. Later current-source behavior, the two-command protocol, and the November 1 error investigation are documented in [RESULTS.md](RESULTS.md).
